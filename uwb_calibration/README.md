# DW1000 UWB 캘리브레이션

Makerfabs ESP32_UWB(DW1000) 기준입니다. 기준 태그 한 개와 앵커 A1~A4를 **한 개씩** 연결하여 각 앵커의 안테나 지연값을 자동으로 찾고, 결과를 JSON으로 저장합니다.

## 먼저 지켜야 할 배치 조건

- UWB 안테나 끝부분이 금속 프레임·배터리·모터·전선에 가리지 않게 로봇 위쪽에 고정합니다.
- 실제 주행 때 사용할 브래킷, 높이, 방향 그대로 기준 태그를 설치합니다.
- 태그와 앵커 안테나 중심의 높이와 방향을 같게 하고, 서로 정면이 보이는 LOS 상태로 둡니다.
- 거리는 기판 가장자리가 아니라 **안테나 중심부터 안테나 중심까지** 줄자로 측정합니다.
- 벽, 바닥의 금속, 사람과 충분히 떨어진 공간에서 모터 전원을 끄고 보정합니다.
- 가능하면 반사가 적은 더 넓은 장소에서 5~8 m를 확보하는 것이 좋습니다. 4 m x 3 m 시험장 안에서 해야 한다면 중앙의 긴 방향으로 `3.000 m` 정도를 확보합니다. 실제로 잰 값이 2.984 m라면 반드시 `2.984`를 입력합니다.
- 보정 중에는 기준 태그와 현재 보정할 앵커 하나만 켭니다. 다른 UWB 장치는 모두 끕니다.

안테나가 로봇 앞쪽에 달려 있어도 안테나 지연 보정은 가능합니다. 다만 로봇 몸체에 의한 오차까지 포함되도록 최종 장착 상태에서 보정하고, 나중에 위치 제어에서는 태그의 전방 오프셋을 IMU yaw와 함께 보정해야 합니다.

## 1. Arduino 라이브러리 설치

이 코드는 일반 Arduino DW1000 라이브러리가 아니라 다음 저장소의 수정된 `DW1000_library`를 사용합니다.

- <https://github.com/jremington/UWB-Indoor-Localization_Arduino>

저장소를 새로 내려받은 뒤 그 안의 `DW1000_library` 폴더를 Arduino 라이브러리 폴더에 복사합니다. 복사한 폴더의 `src` 안에 **`DW1000.cpp`가 반드시 있어야 합니다.** 이 파일이 없으면 `undefined reference to DW1000Class...` 오류가 납니다.

같은 이름의 다른 DW1000 라이브러리가 있으면 충돌할 수 있으므로 기존 `DW1000`, `DW1000_backup` 폴더는 Arduino 라이브러리 폴더 밖으로 옮기고, Arduino IDE 컴파일 로그에서 실제 사용된 라이브러리 경로를 확인합니다. 이 프로젝트 폴더에 전에 받아둔 복사본은 `DW1000.cpp`가 누락된 것이 확인되었으므로 사용하지 않습니다.

Arduino IDE 설정:

- Board: `ESP32 Dev Module`
- Upload Speed: 기본값 또는 `921600`에서 실패하면 `115200`
- Serial Monitor: `115200 baud`, 줄바꿈 `Newline`

## 2. 기준 태그 코드 업로드

기준 태그용 ESP32_UWB에 다음 파일을 업로드합니다.

```text
uwb_calibration/reference_tag/reference_tag.ino
```

기준 태그의 안테나 지연값은 `16384`로 고정됩니다. 네 앵커 모두 반드시 이 태그 하나를 기준으로 보정합니다. 시리얼 모니터에 아래와 비슷하게 나오면 정상입니다.

```text
TAG_READY,address=7D:00:22:EA:82:60:3B:9C,delay=16384
```

업로드가 끝나면 태그를 노트북에서 분리해도 됩니다. 태그와 앵커의 거리 교환은 UWB 무선 통신이므로, 태그에는 보조배터리 또는 안정된 5 V 전원만 공급합니다. 로봇 배터리나 모터 전원을 ESP32_UWB에 직접 연결하지 않습니다. 보정 도우미를 실행하는 USB 케이블은 현재 보정 중인 앵커 한 개에만 연결합니다.

## 3. 앵커 코드 업로드

A1~A4 네 앵커 모두에 같은 파일을 업로드합니다.

```text
uwb_calibration/anchor_autocalibrate/anchor_autocalibrate.ino
```

앵커 번호와 보정 결과는 ESP32 내부 NVS에 저장됩니다. 따라서 소스에서 번호나 지연값을 직접 고칠 필요가 없습니다.

## 4. 자동 보정 실행

먼저 PC 또는 라즈베리파이에 PySerial을 설치합니다.

Windows PowerShell:

```powershell
cd dltla
py -m pip install -r uwb_calibration\requirements.txt
py tools\uwb_calibration_wizard.py --port COM7 --anchor 1 --distance 3.000
```

Raspberry Pi:

```bash
cd ~/dltla
python3 -m pip install -r uwb_calibration/requirements.txt
python3 tools/uwb_calibration_wizard.py --port /dev/ttyUSB0 --anchor 1 --distance 3.000
```

`COM7` 또는 `/dev/ttyUSB0`은 실제 앵커 포트로 바꿉니다. `--port`를 생략하면 포트를 선택할 수 있습니다. 실행 순서는 다음과 같습니다.

1. 기준 태그 전원을 켭니다.
2. A1만 USB로 연결하고 나머지 앵커는 끕니다.
3. 안테나 간 실제 거리를 재고 위 명령을 실행합니다.
4. `CAL_RESULT`와 `Saved:`가 나오면 A1을 끕니다.
5. A2, A3, A4도 각각 `--anchor 2`, `3`, `4`로 반복합니다.

결과는 실행 위치의 `uwb_calibration_results.json`에 합쳐서 저장됩니다. 이미 보정한 앵커를 재실험하면 해당 앵커 항목만 최신 결과로 바뀝니다.

## 5. 성공 여부 확인

최종 출력 예시:

```text
CAL_RESULT,anchor=1,address=81:00:5B:D5:A9:9A:E2:9C,delay=16542,target_m=3.000,mean_m=3.004,std_m=0.018,min_m=2.961,max_m=3.041,error_m=0.004,samples=100
```

권장 합격 기준:

- `abs(error_m) <= 0.03 m`
- `std_m <= 0.05 m`
- 측정 중 `CAL_WARNING,reason=no_reference_tag_range`가 반복되지 않음

기준을 넘으면 안테나 높이·방향과 주변 금속을 점검하고 같은 거리에서 다시 실행합니다. 앵커마다 나온 `delay` 값이 서로 다른 것은 정상입니다.

## 시리얼 모니터로 직접 실행

Python 도우미 없이도 앵커 시리얼 모니터에서 다음 명령을 한 줄씩 보낼 수 있습니다.

```text
A,1
D,3.000
S
```

- `A,1`: 앵커 번호 A1 저장 후 재부팅 (`1`~`4`)
- `D,3.000`: 안테나 간 실측 거리(m)
- `S`: 자동 보정 시작
- `P`: 현재 설정 확인
- `R`: 현재 실행 초기화

## 4 m x 3 m 시험장 설치와 위치 검증

안테나 중심을 기준으로 실제 좌표를 재서 사용합니다. 이상적인 시작 좌표는 다음과 같습니다.

| 앵커 | x (m) | y (m) |
|---|---:|---:|
| A1 | 0.000 | 0.000 |
| A2 | 4.000 | 0.000 |
| A3 | 4.000 | 3.000 |
| A4 | 0.000 | 3.000 |

실제로는 네 변과 두 대각선을 재고 그 측정값으로 좌표를 결정합니다. 직사각형이면 대각선이 둘 다 약 `5.000 m`여야 합니다. 현재 2D 위치 계산 코드는 네 앵커와 태그 높이를 같게 두는 것이 안전합니다.

보정 뒤에는 `(0.5,0.5)`, `(3.5,0.5)`, `(2.0,1.5)`, `(0.5,2.5)`, `(3.5,2.5)`에 태그를 놓고 각 지점에서 100개 이상 측정합니다. 우선 목표는 평균 위치 오차 10 cm 이하, 표준편차 5 cm 이하, 누락률 5% 이하입니다. 이 조건을 확인하기 전에는 자동 군집 주행 속도를 올리지 않습니다.

## 다음 단계

`reference_tag.ino`는 앵커 지연값 보정 전용입니다. 네 앵커 보정이 끝나면 로봇 태그에는 4앵커 위치 계산 코드를 올리고, 앞쪽에 장착된 태그와 로봇 중심 사이 거리도 보정합니다. 현재 기반 라이브러리는 기본적으로 단일 태그 구성이므로 두 로봇의 UWB 태그를 동시에 쓰기 전에 다중 태그 지원 여부를 별도로 검증해야 합니다.
