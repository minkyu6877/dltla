# 적재·운송·퇴장 시나리오

실행 파일: `cargo_mission_gui.py`. 기존 `qr_auto_roundtrip_gui.py`는 이전 시험용으로 유지한다.

```bash
cd ~/qr_robot
python3 cargo_mission_gui.py --headless
```

GUI: http://10.44.212.72:8085 — 이전 GUI/수동 조종 프로그램과 동시 실행하지 않는다.

## 배치와 진행

1. R1 중심 (0.6,0), R2 중심 (0.6,-0.53), 둘 다 +y를 바라보게 배치한다.
   초음파 기준 간격은 약 30cm, 중심 간격은 53cm이다.
2. GUI에서 마지막 퇴장 거리를 0.2~2.0m로 입력하고 설정 적용을 누른다.
   거리가 정해지지 않았으므로 기본값은 비워둔다. 설정 전에는 출발을 차단한다.
3. QR(내용 무관)을 보여주거나 시나리오 시작을 누른다.
4. 두 로봇이 +y 방향을 유지하며 왼쪽으로 60cm 횡이동한다. 적재 위치는 R1 (0,0),
   R2 (0,-0.53)이다. 두 로봇 모두 x=0.6에서 출발해 x=0으로 이동한다.
5. 방향 정렬 후 적재 대기. 이때 화물을 올린다. QR 재인식이나 시간 경과로
   운송을 시작하지 않는다. 적재 완료·출발 버튼은 이 단계에서만 활성화된다.
6. 적재 후 주변을 비우고 적재 완료·출발을 누른다. 센서/간격/방향/정지 상태를
   다시 검사한 뒤 R1 (0,3)까지 직진한다.
7. R1 제자리 시계 90° + R2 후방 공전 후 두 로봇 방향을 맞춘다.
8. +x 직진으로 R1 (3.6,3)에 도착한다. R2 조건부 목표 중심은 (3.07,3)이다.
9. +x를 바라보는 상태에서 둘 다 왼쪽(+y)으로 퇴장한다. 퇴장 거리 d이면
   R1 (3.6,3+d), R2 (3.07,3+d)에서 정지한다. 예: d=0.5이면 y=3.5.

재시작하려면 처음 배치로 옮긴다. 비상 정지 후 적재 버튼으로 중간 재개할 수 없다.
적재 대기 중에는 사람이 초음파에 잡혀도 움직이지 않는다. 출발 확인 시에는
사람/장애물을 비워야 하며, 로봇을 밀어서 간격/방향이 달라졌으면 재배치한다.
적재 후 출발 시 초음파 간격 변화 허용치는 초기 측정값 대비 **±10cm**이다(v6).
예: 초기 29.2cm → 현재 36.9cm는 간격 검사 통과, 39.2cm 초과는 차단한다.
이는 적재 출발 검사만 완화한 것으로, 주행·공전 목표 간격을 새 값으로 바꾸지 않는다.
초음파 18cm 이하 정지, 장애물/센서/방향/정지 상태 검사와 주행·공전 안전 조건은 그대로다.

## 유지하는 보정과 달라진 제어

- 기존 전진 거리 환산 R1 0.8738671085, R2 1.0, IMU 부호, 바퀴 지름 6cm,
  RPM PID/부호/마찰 보정, 공전 횡이동 1.10 및 거리/방향 보정값을 보존한다.
  전진 거리 환산은 기존처럼 양의 차체 전진 성분에 적용하며, 횡이동 중 보정 전진 성분도 포함한다.
- 횡이동은 경로 진행 방향과 차체가 바라보는 방향을 분리한다. R2의 횡속도를
  예전 직진 제어의 0.12로 제한하지 않는다. 첫 구간의 R2 횡속도는 실측 배율로 조정한다.
- 시작 시 실제로 맞춘 중심 53cm와 초음파 측정값의 차이를 그 실행의 중심 오프셋으로
  쓴다. 예: 초음파 30cm이면 중심 오프셋 23cm이다. 이를 원궤도 반지름/편대 표시에도
  공유한다. 19.4cm 축간거리 자체를 변경하는 것이 아니며 config의 기존 보정은 덮어쓰지 않는다.
- 30cm 공전 제어기의 거리/차체 회전 보정값은 유지한다. v8에서는 엔코더 공전
  이동량 동기화를 사용하지 않는다. 기존처럼 출발 시 실제
  초음파 값을 간격 유지 기준으로 기록하고, 공전 반지름은 실시간 거리+중심 오프셋으로 계산한다.
  GUI의 30cm는 배치 안내이며 센서값을 30으로 강제 덮어쓰지 않는다.
- 시작 좌표는 사용자 배치를 기준으로 초기화한다. UWB로 배치를 자동 검증하지 않는다.
- 횡이동 보정을 사용자 요청으로 복구했다. 아래 설명을 참고한다.
- 종점/방향/거리 안전정지 유지. 측면 장애물을 직접 감지하는 센서는 없으므로
  횡이동 및 공전 공간을 확보한다. 적재 후 하중에 따른 미끄러짐은 별도 재시험한다.
- 로그: `experiment_results/cargo_mission_날짜_시간.csv`.
  같은 이름의 `.calibration.json`에 그 실행의 보정값도 저장한다.

### 현재 v8 — IMU 방향으로 공전 종료

GUI 상단의 **보정 ON v8**, **IMU 90° 공전 종료**로 적용 여부를 확인한다.
적재 출발 간격 변화 ±10cm는 유지한다.
시작 좌표/경로/GUI/좌표 초기화는 모두 R1 (0.6,0), R2 (0.6,-0.53) 기준이다.
`config.json`의 다른 프로그램용 시작 좌표는 변경하지 않고 이 프로그램에서만 적용한다.
v4에서 복구한 첫 횡이동/직진 보정과 공전 목표 90도, 기존 근접 안전정지는 유지한다.

- R1 IMU 방향이 +y(90도)에서 목표 +x(0도)에 도달하거나 통과하면 두 로봇의
  공전 명령을 정지한다. 엔코더 거리나 예상 원호 길이는 종료 판단에 사용하지 않는다.
  출발 방향이 조금 다르면 고정 경로의 목표 0도까지 회전한다.
- 자이로 관성 예측으로 미리 완료 처리하지 않는다. 관성과 통신 지연에 따른
  실제 초과 회전은 남을 수 있으므로, 이후 기존 IMU 제자리 방향 정렬을 유지한다.
- v7의 R2 엔코더 공전 진행량 비교, 2도 앞섬 대기, 임시 이동량 배율 약 0.615는
  사용하지 않는다. `cargo_orbit_r2_arc_odometry_scale`은 이 버전에서 읽지 않는다.
- 기존 접선 보정 1.10, 실시간 초음파 반지름/간격 제어, IMU/RPM 차체 회전 보정과
  목표 근처 두 로봇 감속은 유지한다. 엔코더를 모터 속도 제어에서 제거하는 것은 아니다.
- 정지 후 방향 오차 12도 이내에서 기존 정렬에 진입하고, 최종 방향 1도·회전속도
  2도/s·안정 1초 및 정지 후 재확인 조건을 유지한다.
- 자동 정지 해제 변경은 복구했다. 통신/센서 이상, 초음파 근접/거리 이탈,
  제한시간 등의 안전정지는 유지하지만, 공전 추정 이동량 오차 정지는 사용하지 않는다.

IMU는 차체 방향을 측정하므로, 90도 방향 전환이 R2의 정확한 원호 이동이나 정후방
위치를 보장하지는 않는다. GUI의 주황색 R2 좌표는 기존 후면 조준 가정이다.
기존 CSV, `.calibration.json`, `.orbit.jsonl`은 그대로 저장하며 공전 종료 정보에는
두 로봇 IMU 회전각 및 목표 방향을 기록한다. 이번 변경은 로컬에만 적용했고 테스트는
실행하지 않았다. 라즈베리파이에 파일을 복사하기 전에는 그 장치의 코드는 바뀌지 않는다.

- 첫 접근 `APPROACH_LOAD`: 횡이동 거리 환산 R1 약 0.80341, R2 약 0.80886 복구.
- 첫 접근: R2 횡속도에 약 0.96970 배율을 적용해 R1 대비 약 3.03% 낮춘다.
- 처음/마지막 횡이동: 경로 옆 위치 오차, IMU 방향 유지, 좌표계 회전 보정을 복구한다.
  따라서 보정이 필요할 때는 작은 전후/회전 명령도 나간다. 순수 `vx=0,w=0` 고정 모드가 아니다.
- 처음/마지막 횡이동: R2 초음파 간격 보정(최대 ±0.04)과 방향 정렬을 복구한다.
- 마지막 `EXIT_LEFT`: 위치/방향/간격 보정은 사용하지만, 무부하 첫 접근에서 측정한
  두 가지 횡이동 배율은 적용하지 않는다. 이는 기존 v2 적용 범위와 같다.

초음파·IMU 수신 및 비상정지, 센서 유실/근접/간격 이탈 감지는 유지한다.
기존 근접 감속도 두 로봇에 함께 적용된다. v3의 이동 중 3도/8cm 즉시 정지 대신
기존 보정 주행을 복구했으며, 구간 종점의 방향 3도/옆 오차 8cm/과주행 8cm 판정은 유지한다.
두 로봇 상대 방향 15도 초과, 초음파 근접 18cm 이하 등의 기존 안전정지도 유지한다.
3cm 종점 판정, 출발 가속 제한, 종점 감속은 안전한 자동 구간 실행을 위해 유지한다.
기본 속도는 여전히 0.30이며 GUI에서 조절한다. 60cm는 목표 경로 길이이며 실측 보장값은 아니다.

횡이동 종료 뒤의 별도 방향 정렬과 직진 운송은 이전과 같다. 공전 이동량 추정 제어만 제거했다.
**ESP32 모터/엔코더 부호, RPM PID, 모터별 보정은 수동과 동일하게 유지**하며
이번에는 ESP32 업로드가 필요 없다. UWB는 계속 화면 표시 전용이다.

현재 프로필은 `strafe_compensation_enabled=true`,
`strafe_odometry_scales≈[0.80341,0.80886]`, `strafe_r2_command_scale≈0.96970`이다.
`strafe_calibration_scope`와 `translation_phase`로 배율 적용 범위/현재 구간을 구분한다.
로그 옆 `.calibration.json`에 출발 좌표, 접근 길이, 복구한 보정과 원래 실측 근거를 함께 저장한다.

### 복구한 v2 실측값 — 첫 접근에만 적용

`cargo_mission_20260830_202228.csv`의 `APPROACH_LOAD_STOPPED`에서 R1 x=0.00849,
R2 x=-0.03991이지만, 사용자 실측은 R1 x≈0.40, R2가 5cm 더 왼쪽(x≈0.35)이었다.
두 로봇을 처음에 x=2에 나란히 놓았다는 기준이다.

- R1 횡이동 거리 환산: `1.60 / 1.99151 ≈ 0.80341`.
- R2 횡이동 거리 환산: `1.65 / 2.03991 ≈ 0.80886`.
- R2 횡이동 명령: R1 기준 `1.60 / 1.65 ≈ 0.96970` (약 3.03% 감소).

위 값은 예전 2m 시험을 기준으로 계산한 값이다. 이번 경로가 0.6m로 줄어도 원래
측정식의 2m를 0.6m로 바꾸지 않는다. v3에서 끈 값을 v4의 첫 접근에 다시 사용한다.
목표 좌표를 -0.4로 바꾸거나 임의로 화면 좌표를 덮어쓰지 않는다.

선택 설정 키 (기본값은 코드에 포함, 현재 config.json 수정 불필요):
`cargo_approach_strafe_odometry_scales: [R1계수, R2계수]`,
`cargo_approach_r2_strafe_command_scale: R2명령계수`.
위 두 설정은 v4에서 첫 접근 배율에 실제 반영한다.

한 번의 대략적인 2m 실측에 기반하므로 하중/속도/바닥에 따른 오차를 보장하지 않는다.
짧은 60cm 구간은 가속/감속 비중이 커서 기존 배율과 맞지 않을 수도 있다.
우선 **화물 없이 첫 횡이동만 실행 → 적재 대기에서 멈춘 상태로** R1의 실제 x,y,
R2의 상대 좌우 오차를 다시 잰다. 목표 판정 허용오차 3cm와 정지 관성은 남아 있다.
초음파는 횡방향 어긋남을 직접 관측하지 못하므로 R2의 주황색 조건부 위치만으로
나란함을 판단하지 않는다. 재보정에는 CSV와 `.calibration.json`, 실측값을 함께 사용한다.

## UWB는 화면 전용

| 앵커 번호 | 안테나 중심 좌표 (m) |
| --- | --- |
| A1 | (-0.6, 0) |
| A2 | (-0.6, 3) |
| A3 | (4.2, 3) |
| A4 | (4.2, 0) |

- 앵커/태그의 동일 높이 10cm를 가정한다. 태그는 기존처럼 R1에만 있다.
- 기존 태그가 UDP 4220으로 보내는 `ranges_m` 네 값을 **A1,A2,A3,A4 순서**로
  해석해 Pi에서 좌표를 다시 계산한다. 태그 펌웨어의 옛 앵커 좌표로 계산된
  `tag_x_m/tag_y_m/quality`를 새 배치의 위치/품질로 사용하지 않는다.
- 기존 태그가 이 패킷을 현재 Pi IP로 보내고 있다면 이번 표시 기능만을 위해
  태그/로봇 ESP32를 다시 업로드할 필요는 없다. 다른 포맷이면 INVALID_RANGES가 뜬다.
- 보라색 마름모는 태그 위치, +는 앞 11cm/왼쪽 2.5cm 장착 오프셋을 현재 IMU 방향으로
  환산한 R1 중심 추정이다. 태그 높이/몸체 가림에 의한 측정 오차는 그대로 있을 수 있다.
- 이 새 프로그램은 UWB 위치 융합 함수를 비활성화한다. UWB 단절/큰 오차는 화면
  상태만 바꾸고 이동/정지/원궤도/적재 출발 조건에 반영하지 않는다.
- 옛 UWB 방향별 보정 모델/앵커 설정을 새 배치에 재사용하지 않는다. 기존 프로그램의
  config 및 모델은 보존하고 새 화면은 `cargo_mission_geometry.ANCHORS`를 사용한다.
- 주황색 R2는 R1 후면 조준을 가정한 초음파·IMU 편대 추정이며 UWB 좌표가 아니다.
  원래 R2 엔코더 누적 좌표는 체크박스로 따로 표시한다.

## 검증 범위

자동 테스트는 네 구간 순서, 적재 수동 확인, 중지/센서 이상, 횡이동·후진 명령,
60cm 출발/초기 좌표, 첫 접근의 배율 복구, 처음/마지막 횡이동의 보정 명령/종점 정지,
직진/공전 보정 보존,
UWB 앵커 순서/좌표 재계산 및 UWB가 주행에 반영되지 않음을 검사한다.
실제 하드웨어 주행이나 화물 적재 동작은 자동 실행하지 않는다.
